# Repository-scoped engineering guidance

This file applies only to this research repository. It grants no provider/account
permission and cannot override platform rules or user approvals.

Preserve the three tracks and their separate evidence scopes. Run tests before
claiming a repair. Keep runtime state, credentials and personal information outside
source and logs. Never import private King's Theorem code or personal evidence.

Do not silently enable mail, push, calendars, home control, services, tunnels, API
billing or new scheduled tasks. No blanket completion/security/autonomy claims.
Prefer dependency-free synthetic tests and explicit target-host acceptance.

When modifying an upstream-derived file, record the previous and new hash in the
publication change log. Do not claim the original archive manifest validates a
modified component. A good README does not compensate for a failing test.
