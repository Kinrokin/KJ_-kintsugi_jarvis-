# Roadmap and acceptance gates

No date is a promise and no example schedule is an active user commitment.

1. **Resolve attention delivery.** Characterize the actual creation route and device
   behavior; test a specifically approved private alternate channel. Keep the
   notification incident open until repeated end-to-end evidence exists.
2. **Small native household trial.** One routine and one ordinary follow-up with
   explicit skill invocation, private state, accepted ownership, and verified
   notification behavior. Record review time and false alerts.
3. **Improve field evidence.** Capture task/record identity, event timestamps, source
   freshness, run origin (manual vs timer vs Gmail trigger), and exact observation
   scope without publishing personal data.
4. **Bridge compatibility only if it earns complexity.** Verify real account access
   and custom-app confirmation behavior before hosting an MCP endpoint. No fixture
   authentication on a public network.
5. **Target-host acceptance.** Existing computer first; optional Pi later. Test clean
   restart, confined resources, private access, backup recovery, and independent
   outage reporting. Hardware power-loss tests use disposable fixtures.
6. **Thirty-day value trial.** Compare missed obligations, unnecessary interruptions,
   review minutes and maintenance time to the previous routine. Savings are measured
   only when realized. Stop adding machinery that costs more attention than it returns.

High-consequence operations do not automatically graduate to autonomy. Their scope,
provider controls, human authorization, and recovery behavior require separate review.
