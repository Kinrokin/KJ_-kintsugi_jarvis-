# Authorship, provenance and scope

**Project lead: Robert King (Kinrokin).** Robert defined the household problem,
directed the design and red-team iterations, selected constraints, and performed
and reported the live account/device calibration. AI tools assisted with research,
implementation, documentation, and test generation. This is not represented as
unaided hand-written engineering or an independent security audit.

The repository publishes a curated portfolio edition of three existing artifacts:
Household 3.2, Bridge 1.0, and the Spark calibration skill. Original implementation
files are retained byte-for-byte except for any explicitly logged publication repair.
Their per-file lineage is in `evidence/provenance/source_map.json`.

Nested historical ZIPs, raw personal conversations, financial statements,
credentials, live account identifiers, and private phone screenshots are omitted.
This is a new public edition, not a bitwise republication of an earlier release ZIP.
The package verifier manifests are regenerated for this edition. Upstream test
counts are independently rerun here; upstream release receipts are not used as a
substitute for running the code.

King's Theorem is related research by the same project lead. This repository is
not a proof of that theory, does not publish its private implementation, and does
not inherit a license from that separate project. JARVIS is a fictional inspiration;
no affiliation with Marvel, Google, OpenAI, Home Assistant, or Raspberry Pi is implied.

Results described as field observations are a single-operator case study, reported
in the development conversation. They are not an independently instrumented
benchmark of the underlying platform and should not be generalized into an SLA.
