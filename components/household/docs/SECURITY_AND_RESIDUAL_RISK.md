# Trust boundaries and residual risks

## Actually enforced in this candidate

Private household commands validate occurrence context. Source metadata cannot grant authority. The optional mail clients have fixed read-only methods/endpoints/scopes, bounded response/request budgets and no redirect/proxy inheritance. Outbound push needs local configuration, device consent and a fixed provider allowlist. The HTTP application exposes no financial, calendar or grant endpoint. Same-host runtime instances share an OS lock. Uncertain notification attempts are not retried under the same ID. All personal routines remain private.

The inherited operator-only Google calendar code retains provider/account/environment binding, single-use payload approvals, final dispatch-time validity checks, conditional PATCH/readback and reminder-preserving updates. It stays outside the background runtime. It does not authorize banking or write through other native tools.

## Do not overstate these guarantees

- A process with the same OS identity or root/admin access can read/modify the application or databases. Local HMAC/signatures do not stop a hostile same-principal actor. The default development machine is not a hardened separated execution host.
- DPAPI code exists for Windows CurrentUser. It was not run on Windows in this environment. On POSIX, credentials use owner-only unencrypted files. Household data and opted-in browser storage are not application-encrypted. OS disk encryption/ACLs remain deployment responsibilities.
- Neither local lock nor pause controls other computers, Work/native tools, an independent browser, or manual provider changes. No global single-writer claim is made. A missing external guarantee cannot be manufactured by an AGENTS.md or SKILL.md.
- Dispatch pause cannot withdraw a request already submitted. A final-state race remains possible after the last local eligibility check; notices are deliberately generic, reversible information only. Payments/insurance/legal actions are absent.
- Delivery acceptance, client display reports and a human completing an obligation are separate. Provider receipts and prompts cannot prove a toothbrush was used; user-report is sufficient for ordinary habits.
- Structured JSON and escaped DOM text are not perfect prompt-injection defenses. Mail metadata remains untrusted. No LLM, arbitrary source-driven tool calls, body/attachment downloads or code execution exists in this worker.
- Browser cache/outbox protection is opt-in, not encryption. A compromised or shared unlocked device can expose it. A user-enabled generic notification still reveals that a reminder exists.
- The HTTP server is a private-network prototype, not an Internet production server. No public hosting is authorized.
- The direct optional Web Push dependency is pinned; a complete target-resolved supply-chain lock and dependency audit are not supplied. No dependency installation/network-send result is fabricated.
- Host-local health plus an observer on the same host is not independent failure detection. Whole-host outages cannot be announced by a powered-off host.
- Synthetic tests are finite; simulated responses do not certify current OAuth app registration, mailbox schema, push delivery, Windows service behavior or Android storage.

## Stop conditions

Stop new work on account/connection binding mismatch, stale/partial coverage, unknown external result, config drift, unexpected destination, expired identity, failed provider precondition, missing secrets, unsupported host policy or missing authority. Hold the item with a useful reason, not a silent success.

## What remains human-controlled

Account consent; a selected private phone route/certificate; optional dependencies; exact OS startup installation; skill import; any shared-calendar disclosure; high-impact communication; purchases and payments; subscription/essential-service termination; legal/tax/clinical choices; authority restoration; and changes to another person's responsibilities.
