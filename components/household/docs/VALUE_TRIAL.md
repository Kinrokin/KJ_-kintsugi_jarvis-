# Thirty-day household trial

Do not call the prototype useful simply because it is complex. Compare it with the simpler native calendar/reminder workflow you could use instead.

Start with one user-chosen private morning/evening routine, one reviewed email-to-obligation flow, and only later one explicitly approved private calendar canary. The routine experience should support Done, Undo, Snooze, Skip, minimum mode, offline original context and recovery without creating debt-like task backlogs. Fixed commitments never move merely because a flexible routine is late.

Record daily review_seconds, maintenance_seconds, unnecessary_alert, missed_obligation and false_denial. Record actual operating_cost_cents and only evidenced savings separately. The existing measure CLI and authenticated /api/measure accept user-entered samples; these are not independently measured ROI. Do not count projected twelve-month subscription savings as current cash or a requested refund as received money.

Proposed initial targets: median daily review at most 5 minutes, weekly maintenance at most 15 minutes, zero private-to-Family disclosures, no automated high-impact operation, and fewer missed real obligations than the reviewed baseline. These are proposed targets, not achieved outcomes. Failure triggers simplification, not suppressed important alerts.

An unaccepted family assignment is not coverage. The operator can record another person's reported acceptance with a note; JARVIS has not contacted or authenticated that person. Personal tasks stay private regardless of who is mentioned.

The fallback file intentionally contains a minimal private list, not every credential or inbox detail. Sharing it with a family member is a separate user decision. There is no automatic emergency disclosure protocol.
