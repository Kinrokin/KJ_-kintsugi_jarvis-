# Financial and whole-life operations

This is an operating playbook for the authorized Work host plus pure deterministic helpers. It is not a claim that all these services run automatically in the ZIP.

## Real financial inputs
Use the available Finances app for the user's own accounts, balances, transactions, subscriptions, debt, APR or credit. Discover current tools, read linked accounts and history coverage before transaction-grounded conclusions. For income/cash flow, the first query must retrieve broad negative-amount posted inflows across all relevant accounts/dates, include transfers, and omit income-category prefilters. Classify transfers/payroll/refunds/loan proceeds/ambiguous items AFTER retrieval using stored linkage/category/confidence. Missing fields are not no debts. Never silently drop ambiguity.

Record `as_of`, failed/syncing/partial accounts and requested period. In the first sentence of an incomplete current-period total, state that it is posted through that timestamp across the available synced accounts. No full-period definitive number from incomplete data. Current source state must be read rather than lifted from old screenshots. A foreclosure-account balance is not automatically a currently payable monthly mortgage; verify legal/provider status before building a budget around it.

## Helpers included
`forecast` performs dated cash calculations, separates confirmed cash coverage from future-pay dependence, excludes pending income, checks source freshness/completeness and protected floor, and reports the first breach. On same-day uncertainty it treats debits before credits. It is a scenario calculator, not a prediction or authenticated financial feed. `inflows` separates payroll/transfers/refunds/borrowing/ambiguous sources. Purchases and credit-card payments must be reconciled so economic spending is not counted twice by upstream data preparation.

Do not automatically use guessed partner income, hoped-for overtime, available credit or a pending refund as money. Do not use one-time funds as proof a structural monthly deficit is fixed. Consequential advice should use current official sources and applicable professional review, not a permanently embedded benefits table.

## Bill and subscription responsibilities
Track bill → statement/authentic amount → due date → funding/paycheck plan → human payment → provider evidence → posted reconciliation. A reminder, draft, button click or bank aggregation alone does not prove a debt is settled. No money movement route is shipped.

For subscriptions, distinguish promotional emails from current charges; active payment from actual use; service cancellation from a payment revocation; and ending a renewal from deleting stored data. Preserve effective date/receipt; watch subsequent transactions. No cancellation execution is shipped. Essential services, insurance, storage and working tools require explicit, consequence-aware decisions, not 'cancel everything.'

## Household priorities
Protect children, housing, food, medicine, work transportation, sleep, dignity, relationships and future freedom. Family activities and a vacation can be funded goals once supported by cash planning. They are not automatically waste. Do not treat the user's distress, quietness or a one-time purchase as permanent policy.

The attention pattern is: what changed; why it matters; next required action; deadline; what is safe to defer; missing authority. Avoid repetitive nags and dashboards full of unsupported urgency. One bounded task per overload moment is better than an endless administrative backlog.

## Broader capabilities included as helpers/playbooks
Dependency-risk helper separates observed/inferred/unknown transportation or preparation gaps. Flexible planning previews around fixed commitments; it does not reschedule providers. Opportunity funnel asks identity, eligibility, evidence, sensitive-data/upfront-fee risk and expected benefit before interrupting. Compute budget helper limits a run's planned calls/spend; it is NOT a provider billing cap or durable multi-process budget governor.

Project work, including KT and writing, can receive protected time but no repository, runtime, service, database or manuscript is modified by this package. Do not create a second KT writer or change Ollama to install household software. Advanced commercial opportunities remain proposals, not applications or purchases.

## When simpler wins
Keep stable native recurring reminders/autopay that already work unless a specific change is authorized. The assistant should detect exceptions and reduce burden; it does not need to reconstruct every reliable native function. Use ordinary code for dates, sums, policy and deduplication. Expensive reasoning only for consequential ambiguity. No paid API or service starts automatically.
